# IT-Ledi — AML Alert Risk Dashboard (frontend)

Next.js-панель поверх API скоринга оповещений финансового мониторинга: показывает
вероятность того, что оповещение будет передано на расследование (`eskalatsiya`).

Это frontend-часть проекта. Backend (FastAPI + LightGBM) живёт здесь:
https://github.com/asadbek-ai-creator/transaction_backend

## Быстрый старт (Node.js 18+)

Сначала поднимите backend на порту 8000 — см. его README.

```bash
cp .env.local.example .env.local   # при необходимости поменяйте NEXT_PUBLIC_API_BASE_URL
npm install
npm run dev
```

Откройте http://localhost:3000

## Стек

Next.js 14 (App Router) + TypeScript + Tailwind CSS, без внешних UI-библиотек.

## Разделы интерфейса

- **«Один сигнал»** — ручной ввод истории транзакций построчно, результат — дуговой
  индикатор вероятности эскалации и список признаков, повлиявших на оценку.
- **«Пакетная загрузка»** — загрузка CSV (сигналы) и CSV/parquet (транзакции),
  таблица с топ-100 самых рискованных сигналов, кнопка скачивания полного
  `predictions.csv`.
- **«О модели»** — метрики модели и график важности признаков (данные из
  `/feature-importance`).
- **«Живой демо»** — демо-режим для презентации, см. ниже.

Индикатор в правом верхнем углу показывает, доступен ли backend API прямо сейчас.

## Живой демо для презентации (телефон → дашборд)

Для показа жюри есть демо-режим: с телефона имитируется банковский перевод,
а на компьютере (вкладка «Живой демо») в реальном времени появляется оценка риска.

**Это только для презентации** — не часть официальной submission-модели.

1. Убедитесь, что телефон и компьютер в одной Wi-Fi сети.
2. Узнайте локальный IP компьютера (`ipconfig` на Windows, `hostname -I` на Linux).
   Например: `192.168.1.42`.
3. В `.env.local` укажите этот IP вместо `localhost`:
   ```
   NEXT_PUBLIC_API_BASE_URL=http://192.168.1.42:8000
   ```
   Перезапустите фронтенд (`npm run dev`).
4. На компьютере откройте `http://localhost:3000` → вкладка **«Живой демо»**.
5. На телефоне откройте `http://192.168.1.42:3000/phone`.
6. Введите номер карты и сумму, нажмите «Отправить» — на телефоне появится
   «Перевод отправлен», а на компьютере через 1–2 секунды обновится оценка риска.

Телефон **не показывает** оценку риска — только «Перевод отправлен», как в реальном
банковском приложении. Оценка видна только на дашборде.

Для наглядной демонстрации лучше всего работает тип **«Наличные» (`naqd`)** с суммой
от ~40 млн сум — риск растёт заметно и монотонно с увеличением суммы.

## Заметки

- Next.js 14.2.35 (последний патч линейки 14.x на момент сборки). `npm audit`
  показывает ряд advisories, затрагивающих очень широкие диапазоны версий Next.js
  (в основном — Image Optimization API, Server Actions, i18n-middleware — ничего
  из этого в проекте не используется). Перед деплоем в продакшн стоит проверить
  `npm audit` заново и рассмотреть переход на Next.js 15/16.
- Шрифты — системный стек (`-apple-system`, `Segoe UI`, `Roboto`…) вместо Google
  Fonts, чтобы сборка не зависела от сети. Если нужна точная типографика
  (Inter / IBM Plex Mono), верните `next/font/google` в `app/layout.tsx` — но
  тогда сборка потребует доступа к `fonts.googleapis.com`.
